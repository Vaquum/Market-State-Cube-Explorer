# Operator protocol

The committed **24-case minimum operator protocol** required by D11 (PRD-0002 S3, #48 section 4): the tasks an operator sets to real people to find out whether the chart's colours, marks and tools are understood, their addresses on named fixtures, their predetermined answers, the gate, and the scorer. **The sessions have not been run.** Everything below is the instrument; the evidence is the operator's, and until sessions exist the status of every item in "What is outstanding" is **OUTSTANDING**, not passed.

The protocol is `tests/fixtures/palette/operator-protocol.json` (this page is written from it; `tests/unit/operator-protocol.test.js`, U63, fails if they disagree); the scorer is `tools/operator-score.js`. The answers are not taken on trust: `tests/unit/operator-protocol.test.js` recomputes every data-derived answer from the exact-rational reference calculator (`tests/reference`) and the hand-computed trade fixtures, and `tests/browser/operator-cases.spec.js` (B51) opens each case's address on the real page and checks that what the page says (the Inspect readout, the mapping ids) is what the answer says. A case the page does not support fails there before a participant is asked it.

## Running a session

1. **Serve the fixtures.** Each case names a fixture; start it with the command in the table below, open the page on the case's address (the address carries `vis=2` and the appearance, so the colours are the ones the record names), and set the case's theme and input (mouse, keyboard or touch device).
2. **Onboard briefly.** Before the first case, once, at most five minutes, from this script and nothing more: the chart shows trades as cells; colour says how much (or, for a signed measure, which side and how much); a cell with no trades is drawn empty; a cell still being filled is marked open; the legend and the readout (hover, or **E** for Inspect) give the exact number; lines are named by a tag at their end. Do not teach any case's answer. Record that onboarding was given (`"onboarded": true`).
3. **Run the cases in the order the participant is assigned**, one prompt at a time, with the three choices shown. Record the first answer and the time to it. Do not say whether it was right until the session ends.
4. **Palette trials.** After the 24 cases, run the 16 palette trials (below) in the order `node tools/operator-score.js --order <participant number from 0>` prints.
5. **Record before fixing.** The first attempt of every case is the result. If a case is changed or the page is fixed afterwards, rerun it transparently: record the rerun with `"attempt": 2` and the change that prompted it, and keep the first attempt in the table. A rerun never replaces a first attempt.

## The gate (D11)

After the documented onboarding, every participant must answer **every critical case correctly the first time** (the three groups: known zero versus unknown, scale comparison, future information) and **at least 90% of the 24 cases correctly overall** (22 of 24); the pooled overall figure is reported beside the per-participant ones. `tools/operator-score.js` computes it from the recorded sessions and exits 0 only if the gate and the palette comparison both hold. It does not establish population-wide anything: it holds for the people who sat the tasks.

## The palette comparison

The candidate unsigned palette (`slate2`, `slate2-8f7890f7`) is compared with the current one (the checked baseline's `ramp1`, `ramp1-a53783c5`) on identical ordering tasks, each shown in both palettes, in an order balanced across participants (`node tools/operator-score.js --order n`): the palette that goes first alternates, and the tasks rotate, so that over eight participants each task is in each serial position once. Fixture `micro:mixed`, level 0,0, measure Volume; add `&ap=slate2-8f7890f7` or `&ap=ramp1-a53783c5` to the address `#t=2021-01-01T00:00Z~2021-01-01T00:06Z&p=24750~25500&r=0,0&mode=volume&vis=2`. The candidate must not add errors: a task a participant gets wrong with the candidate and right with the current palette counts against it, in any number. The comparison is on this task set with these people and does not establish that either palette is better for a population.

## Participants and what is recorded

Seek more people than the minimum, including people with colour-vision differences where feasible, and record what actually happened: how many, their declared colour vision (typical, protan, deutan, tritan, other, undeclared), their devices, their conditions and the limits that follow. Responses go in a JSON file of this shape (the scorer refuses a session without `"human": true`):

```json
{ "sessions": [ { "participant": "P01", "human": true, "onboarded": true, "colourVision": "deutan", "device": "laptop, trackpad",
   "answers": [ { "case": "OP-01", "answer": "<the choice, verbatim>", "ms": 14000, "attempt": 1 } ],
   "palette": [ { "task": "PT-01", "palette": "candidate", "answer": "a", "ms": 5200 } ] } ] }
```

Missing required operator evidence is **OUTSTANDING** and follows the pre-merge exception rule of the parent issue: it needs the operator's scoped acceptance in the pull request, identifying the outstanding item and its risk. It is never relabelled passed.
